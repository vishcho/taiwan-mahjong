# V0.1 第一版交付紀錄

2026-09-12。依「先出一個版本，有錯誤也沒關係」的指示，先交付可操作的靜態網站；完整 V1 驗收保留在 [實作計畫](implementation-plan.md)。

## 使用

專案根目錄執行 `npm ci`、`npm run dev`。正式預覽執行 `npm run build`、`npm run preview`，開啟 `http://localhost:4173`。建置產物為 `app/dist`，可部署到 HTTPS 網站根目錄。

預設示例由引擎計算：打九萬後為 0 向聽，三索剩 3 張、六索剩 4 張，受入共 7 張。

產物：[靜態版本 ZIP](taiwan-mahjong-v0.1.zip)、[390px 手機畫面](first-version-mobile.png)。ZIP 解壓後以 HTTP 伺服器開啟，或部署至網站根目錄。

## 演算法修正

`123456m789p123s1111z` 是原公式的反例：公式算 0 向聽，實際沒有任何合法的一張進牌能胡。第一版使用合法目標缺牌數減一，此例為 1 向聽；每種目標牌加自己的固定副露最多四張。詳見 [spec §7.3](../taiwan-mahjong-shanten-v1-spec.md)。

原公式 Base-5 table 與完整 DFS 留作測試；Runtime 使用額外的合法目標距離表，並以獨立目標 DP 比對。距離表原始合計 24,375,000 bytes，gzip 合計 505,072 bytes。部署伺服器可能透過 `Content-Encoding` 自動解壓，loader 同時接受已解壓與 gzip 回應，最後以原始資料 SHA-256 校驗。

## 驗證紀錄

- 核心 18 項測試通過，涵蓋 golden、解析錯誤、槓、花牌、被叫走捨牌、受入歸零、改良牌剩餘池、分享還原，以及 100 組固定 seed 交叉比對。
- `npm run typecheck`、`npm run lint` 與正式 build 通過。
- Chromium 四個 E2E 流程通過：輸入／分析／分享還原、公開牌叫牌連結與修正、320／360／390／430px 無橫向溢出，以及快取完成後離線重開與詳情分析。390 × 844 可同時看到主要結果、完整手牌及鍵盤。測試使用本機已安裝的 Chromium revision 1234；WebKit 未能啟動。
- 效能初測見 [benchmark.json](benchmark.json)。環境為 Linux x64、Node 22.22.1，包含改良牌；17 張案例遍歷全部 16 種捨牌詳情。這不是手機實機效能，也不足以判定手機 p95 達標。

## 已知限制與待驗證

- WebKit 本機啟動失敗：缺少 `libxslt.so.1`。iOS Safari、Android Chrome 實機觸控、安全區及安裝流程尚未驗證。
- 尚未完成完整 V1 的大量交叉比對、所有 spec §45 邊界 fixtures、錯誤注入、並列排序與 browser history 的完整 E2E 覆蓋。
- 四張上限修正的盤面仍顯示原公式的代表拆解，會明確標示兩者差異；尚未回溯成完全對應合法目標距離的拆解。代表解最多顯示 256 種。
- 改良牌在開啟詳情時計算；17 張切換候選後須開啟該候選的詳情。
- 本機歷史逐次輸入會自動保存，瀏覽器返回僅用於明確保存、分享、載入的盤面；逐張復原使用左上角按鈕。
- 分享網址與靜態資源目前以網站根目錄為基準，尚未支援部署在子路徑。
- 尚未部署公開網址。
