# 台灣麻將向聽數分析器 V1 實作計畫

> **2026-09-12：已先交付 V0.1 可操作版本。** 依使用者「先出一個版本，有錯誤也沒關係」的指示，交付範圍調整為可啟動的分析器，完整 V1 驗收保留待辦。實作內容與未驗證項目見 [第一版交付紀錄](first-version.md)；下列清單保留為完整 V1 的驗收基準，不代表第一版全部完成。

依據 [V1 spec](../taiwan-mahjong-shanten-v1-spec.md) 與已定版的 [B 配色 × C 排版](visual-directions/selected.html)。此計畫制定時只有文件與固定示例視覺稿，尚無 Vue 專案或分析引擎。

實作順序：**資料模型 → reference 引擎 → 查表引擎 → 完整分析 → 手機介面 → 分享與離線 → 驗收**。核心測試通過後才接 UI。

## 技術與目錄

| 項目 | 採用方式 |
|---|---|
| 前端 | Vue 3、Composition API、TypeScript、Vite；單頁靜態網站 |
| 盤面狀態 | Vue composable 集中管理，透過明確操作更新盤面；核心只接收資料快照 |
| 分析 | 純 TypeScript；單花色查表與 DP 合併；reference DFS 留作驗證 |
| 背景運算 | 完整分析放入 Web Worker；避免改良牌模擬阻塞點牌 |
| 測試 | Vitest：unit、golden、固定 seed 隨機交叉驗證；Playwright：手機操作與離線流程 |
| 離線 | vite-plugin-pwa，快取頁面、SVG、Worker 與查表資源 |
| 專案管理 | npm workspaces、lockfile；初始化時依套件需求固定 Node 與依賴版本 |

Vue 官方提供 [Vite + TypeScript 建置方式](https://vuejs.org/guide/typescript/overview.html)，型別檢查需另跑 `vue-tsc`。背景運算使用 [Vite 支援的 Web Worker](https://vite.dev/guide/features.html#web-workers)；測試與離線整合分別依 [Vitest](https://vitest.dev/guide/)、[Playwright 手機模擬](https://playwright.dev/docs/emulation) 與 [Vite PWA](https://vite-pwa-org.netlify.app/guide/) 官方文件設定。

```text
app/
  src/
    components/           # 牌面、鍵盤、盤面編輯、分析結果、抽屜
    composables/          # 盤面操作、Worker、URL、本機歷史
    workers/              # 分析排程與查表載入
    styles/               # B 配色、C 排版、手機尺寸
  public/                 # PWA 圖示與建置產生的查表資源
packages/mahjong-core/
  src/                    # tile、parser、validation、shanten、分析、codec
  scripts/                # lookup table 產生器
testdata/                 # shanten、effective、improvement、discard、validation、codec
tests/e2e/
output/visual-directions/ # 保留設計基準，正式 app 不依賴原型腳本
```

核心不得依賴 Vue、DOM、network 或 localStorage。查表下載與儲存由 app 處理，再將資料交給核心。

## 1. 專案骨架與資料模型

- [ ] 建立 workspace、TypeScript strict 設定、lint、型別檢查、測試與 build 指令。
- [ ] 定義 `TileId`、`TileCounts`、四家資料、吃碰槓、牌河、花牌與摸牌標記。
- [ ] 固定 `m/p/s/z` 索引；字牌順序為「東南西北白發中」。支援中文與數字混合輸入，無法辨識時指出位置。
- [ ] 每組副露只存一份；被叫走的捨牌以 ID 連到副露，驗證牌種、來源玩家與連結是否一致。
- [ ] 集中計算已知實體牌，驗證單牌最多 4 張、吃碰槓結構、副露數與 16／17 張結構張數。
- [ ] 將編輯中、非法、可分析盤面分開處理；花牌不計入結構張數。

**驗收：** 同一盤面的中文與 notation 輸入得到相同資料；槓為 1 面子、4 張實體牌；被叫走的牌只扣一次。錯誤指出牌種、來源與數量，非法盤面不產生正常分析結果。

## 2. Reference 引擎與基準案例

- [ ] 實作完整 DFS，搜尋面子、眼、搭子與孤張；對子作眼或搭子必須分支，禁止 greedy。
- [ ] 依 spec 計算 `10 - 2M - min(T, 5-M) - P`，保留最佳拆解與穩定輸出順序。
- [ ] 建立獨立的標準胡牌結構判定，驗證 `-1` 與聽牌摸入後的直接胡牌。
- [ ] 建立人工核對的 golden fixtures：已胡、聽牌、一向聽、多重拆解、眼的歧義、副露、明暗槓、花牌、牌數上限。
- [ ] 加入四張同牌等邊界案例；若公式、合法胡牌與有效牌定義產生衝突，以具體反例提出修正，不只用兩套相同公式互相比對。

**驗收：** 固定案例全部通過；拆解可還原原手牌且不重複使用牌；花牌變更不影響向聽。定版原型的 17 張盤面打九萬後，為 0 向聽，三索剩 3 張、六索剩 4 張。

## 3. 查表引擎與 DP

- [ ] 建立可重現的 Base-5 table 產生器，萬筒索共用 Suit Table，字牌另表。
- [ ] 每個 entry 保存 `[meld][pair] => maxTaatsu` 的所有必要狀態；Runtime 合併四門與自己的固定副露。
- [ ] 為最佳拆解保留回溯能力；不能只回傳最小向聽整數，也不必在每次模擬中展開所有拆解。
- [ ] 表檔附格式版本與 checksum；區分產生器、建置產物與 Runtime loader。
- [ ] 逐步比對單門狀態，再以固定 seed 的合法完整盤面交叉驗證 DFS 與 lookup；失敗案例存為 fixture。
- [ ] 量測表檔大小、壓縮後大小、初始化時間與記憶體，再決定儲存編碼。

**驗收：** golden 與交叉驗證結果一致；相同來源產生相同 checksum；表檔錯誤或尚未載入時不輸出分析數字。

依 spec 的兩種狀態數與每筆 12 個 `Int8` 槽位直接儲存，原始資料約 **24.4 MB**。這是容量估算，不是完成後的下載大小；壓縮與離線快取必須納入驗收。

## 4. 有效牌、受入、捨牌與改良牌

- [ ] 16 張有效牌：向聽大於 0 時摸入後枚舉合法捨牌；0 向聽時直接判斷胡牌。
- [ ] 實際受入只加總剩餘大於 0 的有效牌；分開回傳種類數與剩餘總張數。
- [ ] 17 張候選依牌種去重，按「向聽低、受入高、種類多」排序，保留全部並列最佳。
- [ ] 改良牌須同向聽且增加實際受入；回傳摸入前剩餘、最佳捨牌、原受入、新受入與差額。
- [ ] 模擬摸牌將未知剩餘減 1；模擬捨牌只是從暗手移到已知牌，不能加回未知牌池。
- [ ] 依賴維持單向：向聽供有效牌使用，有效牌供受入使用，捨牌與改良牌組合這些基本函式；禁止循環呼叫改良牌。
- [ ] 完整分析使用獨立的模擬快照；cache key 必須包含會影響該結果的暗手、副露與剩餘牌資訊。
- [ ] 17 張已胡牌時直接回傳胡牌與拆解，不推薦捨牌。

**驗收：** spec §45 的案例全部有測試；覆蓋受入 0、摸入即捨出、公開資訊改變排序、並列、只有種類增加而不算改良、輸入資料未被模擬修改。

## 5. Vue 3 直版手機介面

- [ ] 依定版建立配色與元件：`MahjongTile`、`TileKeyboard`、`HandEditor`、`PublicBoardEditor`、`AnalysisSummary`、`EffectiveTiles`、`DiscardOptions`、`ImprovementList`、`DecompositionDrawer`。
- [ ] 主畫面沿用 C 的順序：最佳捨牌／目前向聽、大數字受入、有效牌張數條、手牌、底部鍵盤；套用 B 的墨綠、米色與暖金。
- [ ] 所有牌圖、結果與按鈕改接真實狀態；捨棄原型中固定盤面與只顯示選取的模擬行為。
- [ ] 完成手牌增刪、文字輸入、自己的副露、四家牌河與副露、花牌歸屬、被叫走捨牌的連結與修正。
- [ ] 單次操作原子更新盤面；增刪副露或修改被叫走的牌，不留下重複扣牌或失效連結。
- [ ] 16／17 張狀態由結構張數推導；按狀態頁籤不得憑空加牌或刪牌。保留剛摸牌標記，且不影響排序。
- [ ] 接上 Worker 與請求序號；快速連續輸入時，只採用最新盤面結果，合併尚未開始的重複工作。
- [ ] 顯示編輯中、非法、載入中、計算中、聽牌、已胡、受入 0 與無改良牌等狀態；結果過期時不能假裝是新盤面結果。
- [ ] 17 張優先顯示所有並列最佳，其他候選可展開；切換候選同步更新其有效牌、改良牌與拆解。昂貴明細可按需計算。
- [ ] 支援抽屜焦點管理、鍵盤操作、文字標示及錯誤定位；牌鍵至少 44px，目標 48px 高。

**驗收：** 320／360／390／430px 直版寬度無橫向溢出；390 × 844 基準盤面同屏可見主要結果、完整手牌與鍵盤。小高度、放大文字或較長盤面可捲動，焦點與輸入不被固定鍵盤遮住。原型的三索／六索結果須由引擎算出。

## 6. 分享、歷史與 PWA

- [ ] 定義帶版本的 URL codec，完整保存暗手、副露、牌河順序、花牌、摸牌標記與被叫牌資訊；分享前後重新分析結果相同。
- [ ] 編碼與壓縮為純函式，瀏覽器 URL 與儲存存取留在 app；檢查毀損資料、未知版本及解壓後的大小上限。
- [ ] 分享內容以盤面為主，不保存可重新計算的分析結果；失敗時保留目前盤面並顯示具體原因。
- [ ] 加入最近盤面的 localStorage 與版本處理；browser history 支援盤面返回，點每張牌不必新增一筆導覽紀錄。
- [ ] 設定 manifest、安裝圖示與 Service Worker，快取 app、牌圖、Worker、表檔與解碼所需資源。
- [ ] 完成快取後才顯示可離線使用；更新時避免舊程式混用新表檔，保留尚未存下的盤面。

**驗收：** 分享連結可在另一個瀏覽器還原；已完成首次載入與快取後，斷網重開仍可分析、改良牌計算及還原盤面。無網路、快取失敗或本機儲存不可用時，提示狀態而非清空使用者資料。

## 7. 整體驗收與交付

- [ ] CI 執行 lint、核心與 Vue 型別檢查、unit／golden、固定 seed 交叉驗證、表檔產生與 build；完整大量比對另設可重現指令。
- [ ] Playwright 覆蓋完整輸入分析、吃碰槓、被叫走捨牌、並列比較、錯誤修正、分享還原、返回與離線重開。
- [ ] 自動化檢查 Chromium 與 WebKit；另在可用的 iOS Safari／Android Chrome 實機確認觸控、可視高度、安全區與安裝流程，未測部分明確列出。
- [ ] 用固定簡單／最差拆解盤面，記錄冷啟動、首次查表、16 張完整分析、17 張完整分析的耗時與記憶體；包含改良牌內層的有效牌枚舉成本。
- [ ] 計畫初始效能目標：390 × 844 手機操作不被分析阻塞，暖機後完整分析 p95 以 300ms 為目標；選定測試裝置後固定基準，超標先量測原因，不能刪掉正確性或必要結果換速度。
- [ ] 核對 spec §52 全部項目，更新 README 的執行、測試、建置與離線說明；整理可部署的靜態產物。

**驗收：** 所有必要測試通過；沒有固定假結果；每項 V1 完成條件都有對應驗證。效能數字是本計畫的初始目標，尚未實測。部署平台與網址可在產物完成後決定，不阻擋本機實作。

## 規格補充的處理方式

已定案的 Vue 3、B 配色 × C 排版、標準 5 面子 + 1 眼與離線分析不再重選。下列細節在第一階段補成資料契約與測試：

| 細節 | 實作預設 |
|---|---|
| 17 張已胡牌 | 顯示胡牌與拆解，不再建議捨牌 |
| 輸入尚未滿 16／17 張 | 保留輸入，提示尚缺張數，不顯示正常分析 |
| 可捨牌範圍 | 只枚舉自己的暗手；副露不可拆回候選，不推測額外地方限制 |
| 公開資訊 | 影響剩餘張數與受入；牌河順序、摸切標記不新增排序條件 |
| 最佳拆解 | 採穩定順序顯示代表解，可展開其他等價最佳解；穩定順序不能用來刪掉並列最佳捨牌 |
| 花牌 | 採春夏秋冬、梅蘭竹菊各一張作為初始輸入集合，獨立記錄與驗證，不進結構計算；此集合為 spec 未列出的實作預設 |

若測試證明上述預設與 spec 的核心定義衝突，先提出最小反例與修改建議，確認後同步更新 spec 與 fixtures。
